# App Flow Document

## Onboarding and Sign-In/Sign-Up

When a new user first arrives, they land on the public landing page that features the animated hero section. This page introduces the AI Menu Refresh Platform and invites chefs to sign up or log in. At the top of the page, there are clearly marked buttons for “Sign Up” and “Log In.” Clicking “Sign Up” brings the user to a registration form where they can enter their email, choose a password, and confirm it. Validation immediately checks that the email is well-formed and that the password meets length and complexity rules. Alternatively, chefs can choose a social sign-in option if enabled in Supabase, such as signing in with Google or GitHub, which directs them to the third-party OAuth flow and then back into the app once authentication is complete. Upon successful registration, the user is automatically logged in and taken to the main dashboard. If a returning user clicks “Log In,” they see a form for email and password. If they forget their password, a “Forgot Password?” link opens a dialog or page where they enter their email to receive a reset link. Once the user follows the emailed link and chooses a new password, they return to the login page to sign in again. Signing out is available via a button in the user menu on the dashboard, which ends the Supabase session and redirects back to the landing page.

## Main Dashboard or Home Page

After a successful login, the chef lands on the Dashboard page. The layout includes a persistent vertical sidebar on the left and a top header across the screen. The sidebar lists the main sections of the app by name: Dashboard, Menu Management, AI Recommendations, Analytics, and Settings. The header shows the chef’s avatar or initials, a theme toggle button, and a dropdown for quick sign out. The central area of the Dashboard greets the chef by name and displays widgets such as a summary of current menu items, a prompt to request new AI suggestions, and shortcuts to add a new dish. This default view is built to give an at-a-glance overview of recent activity, pending recommendations, and quick actions. From this main page, the chef can click any sidebar item or click buttons on the dashboard cards, which changes the main content area through client-side routing handled by React Router and ensures a seamless single-page experience.

## Detailed Feature Flows and Page Transitions

When the chef selects “Menu Management” from the sidebar, the page transitions without a full reload to a menu list view. This view uses a table component styled with Tailwind CSS and `shadcn/ui` components. Each row represents a dish, showing its name, price, and last updated date. Above the table, a button labeled “Add Dish” opens a modal dialog powered by the dialog component. Inside this form, built with React Hook Form and Zod, the chef enters the dish name, description, price, and ingredients. Inline validation flags any missing or invalid fields. Submitting the form triggers a TanStack Query mutation to Supabase, and on success the table updates automatically. Editing an existing dish works similarly: an “Edit” button in each row opens the same form dialog pre-filled with data. Deleting a dish prompts a confirmation dialog, and upon confirmation a mutation is fired to remove the dish from the database.

In the “AI Recommendations” section, the chef clicks a button labeled “Generate Suggestions.” A loading state appears with skeleton placeholders while the app sends the chef’s current menu data to the AI service via a secure edge function or backend call. When results arrive, the page displays a list of recommendation cards. Each card shows a suggested dish name, description, and an “Add to Menu” button. Clicking that button opens the same add-dish form, pre-populated with AI data, allowing the chef to tweak details before saving. If the AI call fails or times out, an error message replaces the loading skeletons and suggests retrying or checking the network.

The “Analytics” section reveals interactive charts rendered with Recharts. Chefs can see cost breakdowns, popularity trends, and potential profit projections. They can filter charts by date range or dish category, with controls at the top of the page. Changing filters triggers new queries via TanStack Query, updating the charts in real time. Navigation between these feature pages always returns the sidebar and header intact, ensuring the chef knows where they are and can quickly jump to the next section.

## Settings and Account Management

Clicking “Settings” in the sidebar leads to the account management page, where chefs can update their personal profile. They see form fields for display name, email address, and password change. Changing the email requires entering the current password for security. Updating the password also asks for the old password alongside the new one. Beneath profile settings, there is a section for notification preferences, allowing chefs to toggle email updates for new AI suggestions or system announcements. If the platform offers a premium subscription for advanced AI usage, a billing tab houses subscription status and payment method management. Chefs can enter or update credit card information in a secure payment form. After saving any changes, the page shows a toast notification confirming the updates. A link at the top of the settings page returns the chef back to the main dashboard.

## Error States and Alternate Paths

Throughout the app, form fields validate on blur and on submit, displaying clear error messages next to each invalid field if data does not match the Zod schema. If the network connection drops during a TanStack Query fetch or mutation, the content area shows an error banner with a retry button. Attempting to access any page without a valid session automatically redirects the user to the login page. If the chef’s session expires while on a feature page, they see a notification prompting them to log in again. A generic “Something went wrong” page handles unexpected client-side errors and offers a button to return to the dashboard. For restricted actions like adding payment details, the user is prompted to confirm their password again before proceeding. Every fallback or error state guides the chef back into the normal flow through clear messaging and action buttons.

## Conclusion and Overall App Journey

In summary, the chef begins on a polished landing page, signs up or logs in, and arrives at a cohesive dashboard that unifies menu management, AI-driven suggestions, and analytic insights. They navigate between pages using a stable sidebar and header, perform CRUD operations on menu items, generate and incorporate AI recommendations, and monitor performance through charts. Profile settings and billing are housed in a dedicated section, and robust error handling ensures the chef never feels stuck. With password recovery, session checks, and inline validation in place, the end-to-end journey is smooth from first touch to daily use.
